## 用户选择方案③，真后台已落地

**架构**：零依赖 Node（仅内置模块）单端口服务，SSR + 文件存储。

- `server.js` —— HTTP 路由：SSR 页面、`/api/*`、静态资源、RSS/sitemap/robots。
- `lib/store.js` —— `data/` 目录读写，frontmatter 解析/序列化，原子写入（tmp+rename），版本历史 `data/.history/<slug>/<ISO>__<reason>.md`（保留 40 份），改 slug 时历史目录跟随迁移。
- `lib/markdown.js` —— 自研 Markdown 渲染，先转义 HTML 再拼标签（无 HTML 直通），支持标题/引用/列表/代码块/加粗斜体/链接图片/分隔线。
- `lib/auth.js` —— HMAC 签名 Cookie 会话（12h，无服务端状态，重启不掉线）、timingSafeEqual 比密码、登录限流 6 次锁 10 分钟。
- `lib/render.js` —— 页面模板 + JSON-LD BlogPosting / canonical / OG（服务"被 AI 搜索引擎检索"的目标）。
- `public/assets/site.css` —— 原 kkhome.html 编辑部风格 CSS 原样抽出（纸感底 #f7f3eb、衬线正文、大写字距 eyebrow）+ 详情/笔记/照片/页脚新样式。
- `public/admin.html` —— 后台：登录、文章 CRUD（草稿/标签/实时预览/⌘S/本地草稿兜底/历史版本恢复）、笔记与照片行内编辑、站点设置。
- `tools/smoke-test.js` —— 端到端冒烟测试，起真实子进程打真实 HTTP，61 项断言全绿。

**关键决策与理由**：
- 选 SSR 而非前端渲染 —— 内容必须出现在 HTML 源码里，AI 爬虫与搜索引擎才抓得到。
- 零依赖 —— 服务器上 `node server.js` 就能跑，不用 npm install，不用管依赖安全更新。
- 密码：优先读 `ADMIN_PASSWORD` 环境变量；没有就首次启动生成随机密码写 `data/.admin-password`（避免出现可猜的默认口令）。当前实例用的是生成密码。
- 内容迁移：只搬 kkhome.html 里真实存在的东西。3 篇文章的正文原文里本来就只有摘要，所以标题+摘要原样入库，**没有替用户编正文**。`long-term-rhythm`（原首页置顶卡片）只有标题和一句标语，建为草稿。
- 笔记/照片原文没有日期字段，故留空而**不编造日期**；渲染时空日期不出日期列。
- `/en` 语言开关改为不可点（英文版不存在），避免再造一个死链。
